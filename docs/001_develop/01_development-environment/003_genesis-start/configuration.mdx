This page covers how to add Genesis Start to a project and how to change the way it runs your application. Everything here applies both to the [desktop window](/develop/development-environment/genesis-start/) and to [headless mode](/develop/development-environment/genesis-start/headless-mode/).

## Enabling Genesis Start

Any project created with Genesis Create or `genx init` already has Genesis Start enabled (Genesis Create uses genx to set up the project), so you can skip the rest of this section. The steps below are for a project that came from neither. It can use Genesis Start if it has:

- the simplified project structure
- the Genesis Gradle Settings plugin

To enable it, you need to change two files:

1. The settings file.
2. The build file.

### Amending the settings file

In your project's `server/settings.gradle.kts` file, add `google()` to `repositories` under `pluginManagement`:

```kotlin
pluginManagement {
    repositories {
        // other repositories
        google() // <- add this
    }
}
```

### Amending the build file

In your project's `server/build.gradle.kts` file, add the plugin:

```kotlin
plugins {
    // other plugins
    id("global.genesis.genesis-start-gui") version "1.0.0-beta1"
}
```

In the same file, add `google()` to the `repositories` block under `allprojects`:

```kotlin
allprojects {
    repositories {
        // other repositories
        google() // <- add this
    }
}
```

You need `google()` in both places. The one in `settings.gradle.kts` is only used to find the plugin itself. The plugin then pulls in the libraries its window is built with (Compose Multiplatform and AndroidX), and Gradle looks for those in the `allprojects` repositories. If `google()` is missing there, `genesisStart` fails with an error about missing `androidx.compose.*` or `androidx.lifecycle.*` artifacts, and nothing in the error mentions Genesis Start. You need this even if you only use headless mode.

### The standalone plugin

If you'd rather not add `google()` to your build, use `global.genesis.genesis-start-gui-standalone` instead. It bundles those libraries into a single jar, so your build doesn't need to download them.

Its tasks have a `-standalone` suffix (`genesisStart-standalone`, `writeStartScript-standalone`). Everything else, including the `genesis.start.*` properties, is the same.

:::note
You might see the plugin ids `global.genesis.genesis-launcher-gui` in older projects. These run the same code under older names (the `genesisLauncher` task, `genesis.launcher.*` properties). They are only kept for existing projects and will be removed, so don't use them for anything new.
:::

## Process profiles

A process profile controls how your application's services are grouped into processes. Choose one from the **Process Profile** menu in the window, or with the [REST API](/develop/development-environment/genesis-start/headless-mode/#driving-it-over-rest) in headless mode.

- **Dev Compact** groups as many services as possible into as few processes as possible, which saves processing power and memory. This is the recommended option for previewing your application locally.
- **Compact** groups services into fewer processes, but in a way that would still run in a cluster.
- **Production** runs processes as your project's configuration defines them. See [process configuration](/develop/server-capabilities/runtime-configuration/processes/) for details.

:::tip Saving local resources
If you need to cut down on memory, choose **Dev Compact** before you start any processes.
:::

When you change profile, Genesis Start reloads the project overview for that profile, so the list of processes and scripts changes to match.

## System definition property overrides

Genesis Start lets you override Genesis [system definition](/develop/server-capabilities/runtime-configuration/system-definition/) properties locally. This means you can adjust configuration (such as the database or ports) without changing your project's system definition.

### Where to put override files

- **User level** (recommended for settings you share across projects):
  - `~/.genesis/development-system-definition.properties`
  - `~/.genesis/{service_name}-system-definition.properties`
- **Project level** (for settings specific to one project):
  - `<server root>/.genesis/development-system-definition.properties`
  - `<server root>/.genesis/{service_name}-system-definition.properties`

The project's `.genesis` folder goes in the root of your server project. Use a `{service_name}` file to override properties for that service only.

### Precedence

If the same property is set in more than one file, the highest one in this list wins:

1. Project-level `{service_name}-system-definition.properties`
2. User-level `{service_name}-system-definition.properties`
3. Project-level `development-system-definition.properties`
4. User-level `development-system-definition.properties`

In other words, project files override user files, and service-specific files override `development-system-definition.properties`.

### Recommendations and version control

- **Use `~/.genesis/` for settings you share across projects**: put machine-wide values (for example, database host and port, or common credentials) in your home folder, so they apply to every Genesis project on your machine.
- **Use the project's `.genesis/` for project-specific settings**: you can share these with your team by committing the folder to source control. Don't commit values that are specific to your machine, or secrets.
- If you commit the project's `.genesis/` folder, consider adding `.gitignore` rules for sensitive or machine-specific files.

### Overriding a property for a single run

To override a property for one run only, pass `--system-definition-property KEY=VALUE`. This takes precedence over all four files above, and over the [database connection settings](#database-connection-settings). Repeat the flag to override more than one property. The value is used exactly as you write it, including any trailing spaces.

There's no Gradle property for this flag, so pass it to the [start script](/develop/development-environment/genesis-start/headless-mode/#the-start-script) instead:

```bash
build/genesis-start/start.sh --system-definition-property DbHost=jdbc:postgresql://localhost:5433/genesis
```

:::caution
Values you pass with `--system-definition-property` are visible on the command line of the Genesis Start process, so other users on the same machine can read them with `ps`. Don't use it for credentials such as `DbPassword`. Set those through the [database connection settings](#database-connection-settings) instead, which are passed as environment variables.
:::

## Database connection settings

You can pass your database connection to Genesis Start as Gradle properties, instead of setting it in your project's system definition. Genesis Start passes each one to every Genesis process it starts, as the matching system definition property:

| Gradle property | System definition property |
|---|---|
| `genesis.start.dbLayer` | `DbLayer` |
| `genesis.start.dbMode` | `DbMode` |
| `genesis.start.dbHost` | `DbHost` |
| `genesis.start.dbUsername` | `DbUsername` |
| `genesis.start.dbPassword` | `DbPassword` |
| `genesis.start.dbNamespace` | `DbNamespace` |
| `genesis.start.dbSqlConnectionPoolSize` | `DbSqlConnectionPoolSize` |

You can set these on the command line (`-Pgenesis.start.dbPassword=...`), but it's better to put them in your own `~/.gradle/gradle.properties` file, so the credentials stay out of the project.

For example, to use a local H2 database, set `genesis.start.dbLayer` to `SQL` and `genesis.start.dbHost` to:

```
jdbc:h2:file:~/genesis-local-db/{app_name}/h2/test;DB_CLOSE_DELAY=-1;NON_KEYWORDS=VALUE,KEY;AUTO_SERVER=TRUE
```

Replace `{app_name}` with the name of your application.

The host, username and password don't appear on the command line of the Genesis Start process. They are passed as environment variables instead (`GENESIS_LAUNCHER_DB_HOST`, `GENESIS_LAUNCHER_DB_USERNAME` and `GENESIS_LAUNCHER_DB_PASSWORD`), so other users on the same machine can't read them with `ps`. This applies both to `genesisStart` and to the [start script](/develop/development-environment/genesis-start/headless-mode/#the-start-script).

These settings have the lowest precedence. Any of the [override files](#system-definition-property-overrides) that sets the same property overrides them, and a `--system-definition-property` flag overrides everything.

## Running several instances side by side

### Two projects on one machine

Every process Genesis Start launches is tagged with the Genesis home it belongs to. When Genesis Start starts up, it picks up any of its own processes still running from an earlier run, and ignores processes that belong to a different Genesis home. So if you run Genesis Start for two different projects, neither one shows or stops the other's processes. Two instances pointed at the same Genesis home do share their processes.

### Port offset

Two instances can't both use the default ports. A **port offset** moves every port an instance uses, so that several can run side by side.

:::warning Experimental
Port offset is an experimental feature. To use it, start Genesis Start with `--enable-experimental-features`. There's no Gradle property for this flag, so pass it to the [start script](/develop/development-environment/genesis-start/headless-mode/#the-start-script). Your project's Genesis platform version must also support the feature; if it doesn't, only an offset of 0 is accepted.
:::

How it works:

- The offset is a number from 0 to 99. It is **0** every time Genesis Start starts, and isn't saved.
- At offset 0, nothing changes: every process uses the ports your application configures.
- At any other offset, Genesis Start assigns every service port itself, counting up from `20000 + offset × 100` (so offset 2 starts at 20200). Each service also uses its port + 10000 for ZeroMQ.
- The ports reached from outside the instance (`ClusterPort`, `DaemonServerPort`, `DaemonHealthPort`, `RouterWebPort`, `RouterSocketPort`, `McpPort` and the two ZeroMQ proxy ports) move up from their usual values by the offset. The Web UI follows the offset too.
- These ports are applied on top of any system definition overrides. A `.kts` or config file that hard-codes another service's port, rather than looking it up, doesn't follow the offset. Nor does an MCP server whose `-mcp-server.kts` file sets `routerHttpPort`.

### Setting the port offset

You can only set the offset with the REST API, so you need the REST API enabled (`-Pgenesis.start.restEnabled=true`) even if you use the desktop window. The window shows the offset, but can't change it. Give each instance its own REST port with `restPort`: the offset moves your application's ports, not Genesis Start's own REST port.

Before you change the offset, stop all of this instance's processes and its Web UI.

To set the offset, call `PUT /api/port-offset` with the value you want:

```json
{"offset": 20}
```

Or let Genesis Start choose one:

```json
{"offset": "auto"}
```

With `"auto"`, Genesis Start tries 2, 4, 6 and so on up to 98, and takes the first offset whose ports are all free. It steps by 2 because some default ports come in adjacent pairs, so two instances one offset apart would clash.

Then start your processes as usual. `GET /api/port-offset` shows the current offset, the full list of ports, and whether a non-zero offset is available (and if not, why).

If Genesis Start restarts and picks up its own running processes, it uses the offset they were started with. If they were started with different offsets, it resets to 0 and refuses to start anything (with `409 MIXED_PORT_OFFSETS`) until you have stopped them all.

These are the errors you might see. The [Swagger UI](/develop/development-environment/genesis-start/headless-mode/#driving-it-over-rest) has the full list.

| Error | Meaning |
|---|---|
| `422 PORT_OFFSET_NOT_SUPPORTED` | Your project's platform version doesn't support a port offset. |
| `422 EXPERIMENTAL_FEATURES_DISABLED` | Restart Genesis Start with `--enable-experimental-features`. |
| `422 PORT_OFFSET_INVALID` | The value isn't a number from 0 to 99, or `"auto"`. |
| `409 PROCESSES_RUNNING` | Stop this instance's processes first. Asking for the offset that is already set always succeeds. |
| `409 NO_FREE_PORT_OFFSET` | `"auto"` found a port in use at every offset it tried. |
| `409 PORT_IN_USE` | Returned when you start a process: one of the ports for the current offset is already taken. If two instances ask for `"auto"` at the same moment, they can choose the same offset; ask for `"auto"` again. |
| `409 MIXED_PORT_OFFSETS` or `UNKNOWN_SERVICE_PORTS` | Processes picked up from an earlier run disagree about their ports. Stop them all to clear this. |

### Seeing the port offset in the window

The status bar shows **Port offset N** on the left. **View → Port Offset…** opens a dialog with the ports for the current offset, why a non-zero offset isn't available (if it isn't), and the offset each running process was started with.

If a process was started with a different offset from the current one, its row in the process list has an **offset N** badge.

## Gradle property reference

You can set each of these properties on the command line (for example, `-Pgenesis.start.restPort=18080`) or in a `gradle.properties` file: your project's, or your own `~/.gradle/gradle.properties` for anything personal such as credentials. The `genesis.start.` prefix is optional (`restPort=18080` also works); if you set both forms, the one with the prefix wins.

The properties apply to `genesisStart`, and to `writeStartScript`, which builds them into the script it writes.

| Property | Default | What it does |
|---|---|---|
| `genesis.start.headless` | `false` | Runs without a window, driven over REST. See [headless mode](/develop/development-environment/genesis-start/headless-mode/). `-Pgenesis.start.headless` on its own counts as `true`. |
| `genesis.start.autoLaunch` | `false` | Runs Bootstrap and Launch as soon as the window opens. Desktop window only. `-Pgenesis.start.autoLaunch` on its own counts as `true`. |
| `genesis.start.restEnabled` | `false` | Starts the REST API. You need this for headless mode, and to change the [port offset](#port-offset). |
| `genesis.start.restPort` | `8080` | The REST API's port. Ignored unless `restEnabled=true`. |
| `genesis.start.restBasePath` | `/api` | The path the REST API is served under. Ignored unless `restEnabled=true`. |
| `genesis.start.restMaxRequestBodyBytes` | 50 MiB | The largest request body the REST API accepts. Ignored unless `restEnabled=true`. |
| `genesis.start.dbLayer`, `dbMode`, `dbHost`, `dbUsername`, `dbPassword`, `dbNamespace`, `dbSqlConnectionPoolSize` | | [Database connection settings](#database-connection-settings) passed to every Genesis process. |
| `genesis.java.version` | `17` | The Java version Gradle uses to run Genesis Start. |
| `genesis-start.renderApi` | | The graphics backend the window uses (for example, `OPENGL`). Defaults to `OPENGL` on Windows under Citrix; otherwise it is chosen automatically. |

`--system-definition-property`, `--enable-experimental-features` and `--rest-api-version` aren't available as Gradle properties. Pass them to the [start script](/develop/development-environment/genesis-start/headless-mode/#the-start-script) instead.
