## `genesisInstall`

The `genesisInstall` command installs and configures the Genesis application. It processes system definitions, database schemas, and other configuration files to prepare the environment.

### Blocking genesisInstall in containerised environments

To prevent accidental execution of `genesisInstall` in containerised environments (such as Docker), you can block this command using the `BlockGenesisInstall` system definition property.

By default, Docker runtime images generated by the Genesis Gradle plugin set the environment variable `GENESIS_SYSDEF_BlockGenesisInstall=true`. This blocks `genesisInstall` from running inside the container.

If you attempt to run `genesisInstall` when it is blocked, the command prints a warning and exits cleanly without performing any changes:

```text
WARNING: genesisInstall cannot be executed because BlockGenesisInstall is set to "true".

This typically indicates the application is running inside a Docker container, where genesisInstall should not be used.

To apply changes:
- Use environment variables for system definition updates
- For configuration or GPAL changes, build and redeploy a new image
```

###### Syntax

You can configure this behaviour in your `genesis-system-definition.kts` file:

```kotlin
systemDefinition {
    global {
        item("BlockGenesisInstall", "true")
    }
}
```

Alternatively, you can override this setting using an environment variable:

```bash
export GENESIS_SYSDEF_BlockGenesisInstall=true
```

To allow `genesisInstall` to run (for example, during local development or troubleshooting), set the value to `false`:

```bash
export GENESIS_SYSDEF_BlockGenesisInstall=false
```
